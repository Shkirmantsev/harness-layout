# Adopt dated OpenSpec state

## Why

The user explicitly requests the donor's dated accepted-spec convention and one
central “actual is” project state. Current undated identities lack that convention
and the workflow page lists only a subset as capabilities grow.

## What Changes

- Migrate accepted identities using original Git acceptance dates and live delta paths.
- Adopt donor undated active IDs and dated archives in shared project guidance.
- Add one central accepted-state inventory and enforce naming and coverage.

## Capabilities

### New Capabilities

- `2026-10-03-openspec-governance`: dated identities and central accepted-state inventory.

### Modified Capabilities

- `2026-10-03-portable-harness-tooling`: dated strict-validation layout.

## Impact

OpenSpec paths, shared guidance, validation, tests and explanatory Wiki only.
Linux/Windows support is retained. Historical archives remain unchanged. No product
business logic or dependencies change. The user owns dev-to-main PR creation/merge.
