# QA report — Harness Layout Native v3.2.0

## Architecture selected as source of truth

The uploaded files represented two different generations of the framework. This revision standardizes on the **simplified native architecture** implemented by `harness-layout-native-final(1).zip`:

- Claude Code -> dedicated remote Hermes MCP **control** sidecar;
- OpenCode -> project-local `hermes_*` tools -> native Hermes `/v1/runs` API directly;
- Codex -> no Hermes transport in this phase;
- Hermes repository/media operations -> native SSH-backed Hermes tools through the dedicated ACL-limited main-PC account;
- no binding DB/project bridge/attachment relay/project-file MCP/second Hermes runtime;
- no Firecrawl stack; Crawl4AI is the default optional crawler.

The standalone sidecar and remote-finalization instruction were rebuilt to this same contract.

## Functional corrections applied

- Sidecar upstream base changed from `http://127.0.0.1:8642/v1` to server root `http://127.0.0.1:8642`; health now correctly probes `/health`, while run APIs use `/v1/...`.
- `hermes_steer` payload corrected from `{"text": ...}` to Hermes v0.20.5 contract `{"input": ...}`.
- Sidecar no longer sends `model=hermes-tailscale-worker` on `/v1/runs`. Hermes treats a `/v1/runs` model field as a true per-request model override; the worker profile's provider/model must remain authoritative.
- New Hermes session ID is generated by default for each unrelated Claude delegation. Intentional continuation requires passing the previously returned `session_id`.
- `hermes_wait` returns on `waiting_for_approval`; a separate validated `hermes_approve` tool was added. No automatic approval path was added.
- OpenCode no longer wraps Hermes as a model-backed agent; native `/v1/runs` custom tools are the only OpenCode delegation path.
- Local model output cap increased from 512 to 4096 tokens to avoid routine coding-response truncation.

A live pip-install/import of the refreshed dependency set could not be executed in this artifact environment because external package installation is unavailable here.

## v3.1.1 regression fix

- LiteLLM uses the official `ghcr.io/berriai/litellm:v1.98.0` image directly; no `local/harness-litellm` image exists.
- `make pull` uses Compose `--ignore-buildable`, so local MCP/edge images are built by `make build`/`make up --build` instead of being pulled from a registry.
- Added architecture tests to prevent both regressions.


## v3.2.0 OpenCode Hermes delegation fix

- Removed the OpenCode `hermes-remote` model provider and generated `@generated-hermes` model/subagent path.
- Added project-local OpenCode custom tools `hermes_delegate`, `hermes_status`, `hermes_wait`, `hermes_result`, `hermes_steer`, `hermes_approve`, and `hermes_cancel`.
- The tools call native Hermes `/v1/runs` and run-control endpoints directly, with no MCP or LiteLLM hop.
- Added generated `.generated/opencode-hermes-runtime.json`; the API key remains in mode-0600 `.generated/hermes-api-key`.
- `hermes_approve` is configured as an OpenCode `ask` permission; other Hermes control tools are allowed.
- Added regression tests preventing a return to the model-backed Hermes provider path.
- `PROJECT_ROOT=auto` now resolves to the absolute harness/project root during `make init`.
- Sidecar copy now stages under `/var/tmp` to avoid SSH-user/runtime-user home permission mismatches.
- Sidecar systemd installer now uses the real Linux passwd-database home instead of `$HOME`, avoiding profile-shell systemd-unit misplacement.
